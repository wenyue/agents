# 编写 Rules 和 Skills

**先路由：**一个 Rule 拥有一项政策；一个 Skill 拥有一项完整任务。根据已接受的意图和已验证的
证据重建每个选中的产物。现有产物和 diff 是变更证据，绝不是最终结果的形状。

先应用 `writing-for-agents` 的 context pointer、信息层级、相关性、裁剪和 Skill invocation mechanics。
本 Skill 负责 Rule 或 Skill 路由、两者共同的编写契约，以及两类专门指引之间的边界。

清晰、可执行和只有一种无歧义解读优先于精简。只有满足这些条件后，才在不隐藏、合并或删除会改变
含义或行为的信息的前提下尽量精简产物。保留每项有依据的决定和安全边界。没有当前证据或用户明确
批准，不得在语义上改变任何指令或要求。

## 1. 路由产物

根据请求结果的语义分类，而不是根据当前文件名或目录分类：

| Target 语义 | 路由 |
| --- | --- |
| 一项在条件成立时持续约束行为的政策 | 阅读 [`references/rule-authoring.md`](references/rule-authoring.md)。 |
| 一项有触发、有动作，并有明确完成、停止和失败出口的任务 | 阅读 [`references/skill-authoring.md`](references/skill-authoring.md)。 |
| 同时包含政策和过程 | 将其拆成分别拥有的产物，并阅读两份 reference。 |

在任何写操作前，完整阅读每份选中的 reference，并将其与本共同契约一起应用。语义仍有歧义时，
检查预期权限、所有者、适用条件和执行生命周期。在写操作前解决每个可能改变路由的未知项。

当每个请求产物都有一种有依据的类型和所有者、每个混合产物均已拆分，并且每份选中的 reference
均已加载时，路由完成。

## 2. 收集共同承重证据

只收集能够改变产物含义、所有者、适用性、执行、分发或验证的证据：

- 请求的结果、约束、已接受决定、安全边界和排除的职责；
- 产物所属 family、更宽和更窄的所有者、真实用法、强制或执行点、wrapper、registry、manifest、
  mirror 和契约测试；以及
- 在声称共享或生成行为时使用的代表性 target 和支持的 override。

将现有产物作为证据和遗漏检查，而不是大纲。将 runtime fact 保留在其所属配置中，将变更历史留在
最终产物之外。当另一个所有者超出批准范围时，报告该依赖，并在修改前获得批准。

当每项路由、契约选择，以及可能影响结果的仓库或平台声明都有依据，且剩余未知项无法改变契约时，
证据充分。

## 3. 重建完整产物

按照每个选中产物今天应有的状态编写：

- 根据已接受意图和已验证证据综合一个完整候选。保留预期结果、有依据的决定和安全边界；删除失效、
  重复、矛盾、过渡或错放的内容。
- 以产物的 governing model 和边界开头，而不是主题分类。当一个精炼的 leading term 可以组织工作时，
  只定义一次并始终如一地使用。
- 在拥有每项当前要求的最窄产物或自有资源中只表达一次。只修改执行、加载或分发结果所需的资源、
  wrapper、registry、manifest、mirror、generation input 和契约测试。
- 根据当前条件和行为陈述稳态契约。只有当前输入仍可能触发迁移行为时才保留，并明确触发和退役条件。
- 使用可观察的条件和结果。用获得评价词的具体属性替代评价词。
- 优先使用正向指令。只有为了阻止合理可预见的有害捷径才使用否定，并同时给出要求的替代行为或
  持久后果。

受跟踪产物使用仓库相对路径、产物根目录相对路径或稳定协议所拥有的路径。根据已发现的根目录或任务
输入推导 runtime 绝对路径。除非路径属于 runtime 契约，否则通过 canonical name 引用其他 Rule 或
Skill。

## Markdown 承载含义

Markdown 是语义结构，不是装饰。每种形式都必须改变另一个 Agent 定位、理解或执行产物的方式；删除
不会改变结果的格式。

| 形式 | 用途 |
| --- | --- |
| Headings | 稳定语义区域或真实分支。将 governing model 放在分支细节之前。 |
| Numbered lists | 顺序会改变正确性、安全性或生成结果的有序动作。 |
| Bullets | 没有执行顺序的同级要求或参考项。 |
| Checklists | 具有明确主体、动作或属性和可观察结果的独立义务或 gate。 |
| **Bold** | 少量用于组织产物的 leading term、不变量或精确对比。 |
| Fenced blocks | 精确语法、模板、命令或输出形状。每项规范性要求都必须在 block 外陈述。 |
| Blockquotes | 必须与周围内容分开的简短字面陈述、预测或对比。 |
| Tables | 精确映射或重复字段比较，而不是长篇正文或有序工作。 |
| Links | 周围文字明确说明何时必须读取目标的 context pointer。 |

保持足够浅的嵌套，使 governing model 始终可见。只有为解决实质歧义才添加示例；保持最小，并在示例
外以规范形式陈述要求。

## 完整产物 Gate

脱离 diff 阅读每个完整候选，并走查每个选中分支。只有满足以下条件，结果才通过：

- 另一个 Agent 无需隐藏上下文，也无需虚构条件、步骤或出口，就能发现每个产物何时适用并使用其
  完整契约；
- 类型、所有者、边界，以及选中 reference 要求的每个字段均明确或可验证地不适用；
- 每项当前要求和有依据的决定都只在其唯一所有者下出现一次；
- 每项声明都有依据，每个必要的自有和分发表面一致，且没有改变无关所有者；
- 每份选中 reference 的专门 gate 均通过；并且
- 裁剪后仍然清晰且可执行。

任何路由、所有权、边界、证据、分支或专门 gate 缺口仍存在时，返回相关步骤。产物尚未准备好验证。

## 证明结果

- 执行每份选中 reference 要求的证明。两种类型同时存在时，分别保留 Rule 和 Skill gate 的证据。
- 以结构方式比较语言 mirror。保留路径、命令、标识符、code block、产物 class 和行为。
- 对每个变更的自有、发现、生成或分发表面运行当前 validator、契约测试和 diff 完整性检查。
- 报告任何失败命令的确切命令、最终退出状态、相关输出，以及每个未验证表面。

## 获取独立审查

将审查视为尝试证伪候选，而不是批准形式。每个新编写或实质更新的 Rule 和 Skill 在适用证明运行后，
都必须由全新 subagent 审查。编写者自行审查不能满足此 gate。

1. 为每个候选启动一个全新 reviewer。向其提供完整候选、其自有资源和发现或分发表面、已接受请求和
   证据，以及准确验证结果。要求其应用本 Skill 和选中的 authoring reference。不要提供 diff、编写者
   的推理、疑似缺陷、预期修复或预期答案。
2. 指示 reviewer 返回 `PASS` 或 `FAIL`，应用完整产物 Gate 和选中的专门审查，走查每个实质分支，
   并为结论引用产物证据。`PASS` 表示没有阻塞缺陷。`FAIL` 要明确每个违反的 gate、具体失败场景，
   以及当前证据是否强制得出唯一修正，还是需要新决定。
3. 只有修正由已接受意图和已验证证据唯一确定、保持在已批准范围和所有者之内，且不需要新政策、
   行为、权限或外部副作用时，才自动修复 `FAIL`。由编写 Agent 应用修复，重新运行每项受影响证明，
   然后将完整修订候选交给另一个全新 reviewer。
4. 当一个发现允许多种实质不同的修正，需要缺失的意图、证据、权限、范围或外部副作用，或与已接受
   要求冲突时，停止并报告用户。报告准确发现、无法安全修复的原因、需要的决定，以及每个仍未审查
   或未验证的表面。

如果无法启动全新 subagent，将审查报告为不可用，且不得声称产物完成。只有最新的全新 reviewer 返回
`PASS`，并且每个较早发现都已经修复并重新审查，或由用户明确解决，独立审查才完成。

## 完成

只有完整产物 Gate、每个选中的专门 gate、每项适用证明和独立审查均通过，工作才完成。报告每个
产物的类型和所有者、最终结构、保留的决定、实质变更、移动或删除的内容和资源、每个变更的发现或
分发表面、已批准依赖、审查结论和修复、未解决或未测试表面，以及准确验证结果。
