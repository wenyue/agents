# 重构代码

在不改变可观察行为或外部契约的前提下重组内部代码。

## 前置条件

- 确定具体目标和结构问题。
- 阅读适用的仓库规则、目标代码、附近的既有模式和受影响的调用方。
- 建立能够保护待保留行为的测试或可观察示例。

## 工作流

1. 定义必须保持不变的可观察行为和外部契约。
2. 找出足以消除已指出问题的最小且完整的内部结构。
3. 更新实现，以及所有与已淘汰内部结构耦合的测试。
4. 删除已批准范围内过时的内部分支、adapter 和辅助函数。
5. 运行项目支持的相关 formatter、静态检查和测试。
6. 确认待保留行为仍然通过同一个外部 interface。

只有已批准的行为保持型结果确实需要时，才引入 framework、extension point、compatibility layer 或
test-only interface。

## 架构边界

- 当用户要求在整个代码库中寻找架构改进机会时，停止并提示用户调用
  `improve-codebase-architecture`。
- 当改动需要选择 interface、seam、adapter 关系或测试表面时，在实现前应用
  `codebase-design`。
- 当所选设计会改变公共 interface、持久化格式、协议、集成或用户可见行为时，停止并提示用户带着
  已确认的设计或对应 specification 调用 `implement`。

## 停止条件

- 无法确定具体目标或待保留行为时停止。
- 请求结果需要改变外部契约或可观察行为时停止。
- 现有验证无法区分重构和行为回归时停止。

## 结果

报告已消除的结构问题、保留的行为与契约、修改的内部表面、删除的过时代码，以及实际执行的验证。
