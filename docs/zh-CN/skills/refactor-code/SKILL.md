# 重构代码

重组一个具体目标，同时不改变其调用方或外部使用者能够观察到的内容。

## 确立重构

1. 确定目标、结构问题、已批准范围和预期内部结果。
2. 阅读适用的项目 Rule、目标代码、调用方、测试和附近的既有模式。
3. 定义**保留边界**：必须在现有调用方 seam 保持稳定的行为和外部契约，以及能够区分保留边界
   成立与回归的证据。
4. 确认所选结构属于实现细节，并且每一项计划写入在已批准范围内都有 owner。

## 路由相邻工作

- 对于纯符号或文件重命名，在写入前停止本次运行并交接给 `rename-code`。
- 对于在整个代码库中寻找架构改进机会，在写入前停止本次运行并交接给
  `improve-codebase-architecture`。
- 当重构需要选择 interface、seam、adapter 关系或测试表面时，先应用 `codebase-design`。只有结果
  仍是内部且保持行为的改动时，才回到这里继续。
- 当结果会改变公共 interface、持久化格式、协议、集成或用户可见行为时，停止并把已确认的设计或
  specification 交接给 `implement`。

## 重组内部结构

1. 选择能够消除问题的最小且内在一致的结构。只有已批准结果需要时，才添加 framework、extension
   point、compatibility layer 或 test-only interface。
2. 更新范围内的实现。只有为了让行为断言继续位于受支持的调用方 seam，才调整与已淘汰内部结构
   耦合的测试。
3. 在调用方迁移到新结构后，删除过时的内部结构。
4. 运行受影响表面所需的全部项目检查，包括针对保留边界的聚焦证据。
5. 对照已批准范围和保留边界检查改动表面。如果本次重构造成范围内回归或尚未完成，执行一次
   Correction Pass，并重新运行所有受影响检查。

## 结束本次运行

- 只有问题和过时内部结构都已消除、保留边界在受支持的调用方 seam 仍然成立，并且所有必需检查
  均通过时，才为 **Complete**。
- 当相邻工作路由适用；无法确定目标、边界、范围、owner 或区分性证据；或者请求的结果需要改变
  外部契约时，**写前停止**。报告路由、缺失的决定或证据，并保持重构未启动。
- 当 Correction Pass 后检查仍失败、不存在范围内修正，或者证据已无法区分重构和回归时，
  **写后失败**。保留有用的部分状态，并报告确切失败以及所需 owner 或决定。

写入后，failure 优先于同时出现的 stop condition。在 handoff 中包含该 stop 事实，而不是扩大范围、
改变契约或臆造项目事实。

## 交接

报告已消除的结构问题、保留的行为与契约、修改的内部表面、删除的过时代码、确切检查与退出状态、
执行过的恢复，以及所有未解决或未测试的表面。
