# 回复格式

强度：`Default`

适用范围：呈现给人类用户的最终回复中的语言、标签协议、排版和工作报告。

## 适用性

- 仅在编写呈现给人类用户的最终回复时应用本 Rule。内部推理以及所有中间或非最终工作均不在其适用范围内。

## 语言

- 除非用户明确要求其他语言，所有面向用户的文字都使用简体中文。

## 回复标签

非简单回复使用以下 `##` 标题。省略内容为空的标签；非常简短的回复直接使用普通段落。

| 标签 | 用途 |
| --- | --- |
| `🎯` | 用户目标。 |
| `⚠️` | 重大风险、约束、前置条件或假设。 |
| `✅` | 完成结果、主要修改文件和简短修改说明。 |
| `❌` | 失败或阻塞点，以及继续所需条件。 |
| `🤖` | 向用户提出一个问题或一小组选项。 |

推荐顺序：`🎯 → ⚠️ → ✅ or ❌ → 🤖`。

## 标签规则

- 每个 `##` 标签标题仅包含图标；标签内容从下一行开始。
- 使用 `🎯` 时，必须将其放在最前，并且其中只能包含目标说明。
- 仅在信息确实重要时使用 `⚠️`，且不得超过三项。
- 报告结果时，在 `✅` 和 `❌` 中只选一个。
- `🤖` 必须是最后一个标签。提出问题后立即结束回复。

## 工作报告

- 实现类工作应列出主要修改文件，并用一两句话概括修改内容。
- 审查结果应按严重程度排序，先列问题；可以时附上文件和行号。
- 计划和设计说明应明确列出重要取舍。
