# 规则配置

强度：`Mandatory`

适用范围：规则强度、优先级、归属、激活、语义冲突和项目编号。

## 强度等级

- `Mandatory`：必须遵守，除非更高优先级的指令另有要求。
- `Default`：默认遵守；如果任务本身或更具体的规则有充分理由，可以调整。
- `Advisory`：可在有帮助时结合任务实际情况采用。

## 优先级

在系统、开发者和用户的直接指令之后，按以下顺序解决规则冲突：

1. 强度：`Mandatory` > `Default` > `Advisory`。
2. 相同强度时的归属：项目 > 插件。
3. 相同强度和归属时的具体程度：更窄文件范围 > 更宽文件范围 > 始终生效。
4. 其余插件规则冲突按注册表顺序决定，项目规则冲突按项目文件顺序决定。

低强度项目规则不得覆盖高强度插件规则。

## 语义冲突

- 配置程序不得尝试推断语义冲突。
- 适用规则要求不兼容行为时，只进行确认冲突所需的只读调查，然后在任何副作用前停止。
- 报告冲突规则的 ID、来源、强度、范围和不兼容要求，并请用户解决冲突。

## 规则归属

- 每份插件规则的政策只保留在 `rules/registry.json` 注册的一个源文件中。
- 每份项目规则的政策在 `.agents/rules/` 下只保留一个源文件。
- 各平台的规则包装文件必须保持精简：可以包含平台要求的元数据或运行时字段，
  再加一个指向所属规则的引用；所有政策都留在所属规则中。
- 包装文件的路径、模板、生成方式和其他运行时事实由对应的平台配置或目录负责。

## 编号

| 范围 | 适用内容 |
| --- | --- |
| `00–09` | 项目规则：工具、约定、结构和实用工具。 |
| `10–19` | 模块规则：功能、界面和边界明确的子系统。 |
| `20–29` | 领域规则：测试及其他横切关注点。 |
| `30–39` | 包和项目插件规则。 |

插件规则使用描述性的 `core-*` 和 `file-*` ID，不使用数字名称。项目规则使用上述数字范围，
并遵循此插件所有的优先级契约。
