# Python 指引

强度：`Default`

适用范围：Python API 形态、类型、数据建模、导入、错误、异步资源、测试和工具归属。

## 风格与类型

- 编写明确、可维护的 Python，使数据形态和控制流易于审查。
- 行为应归属于其状态或不变量的所有者；优先使用直接代码，不使用反射、monkey patch、炫技式元编程，
  也不为单一调用点添加宽泛工具。
- 使用类型标注澄清契约，不要让仅类型修改暗中改变行为。
- 为公共和可复用边界添加标注，并明确返回类型；仅执行副作用的函数使用 `-> None`。
- 类型标注语法应兼容仓库声明的 Python 版本范围和邻近代码风格。
- optional 值的表达应与邻近代码一致；具名状态能让契约更清晰时，不使用隐式 `None` sentinel。
- 在边界使用具体集合类型；当修改不属于契约时，使用 `Mapping`、`Sequence` 和 `Iterable` 等只读
  抽象。
- 仅在真正的动态边界保留 `Any`，并在值进入领域逻辑前收窄类型。
- 当 `Protocol`、dataclass、enum、literal 和类型化领域模型能明确受支持状态与数据形态时，优先
  使用它们。

## 函数与数据

- 在首次使用附近声明变量，为含义不明确或空的初始值添加标注，并让 nullable 值只存在于尽可能窄的
  路径中。
- 每个角色使用一个精确变量名，不要让同一名称承载不同类型的值。
- 函数签名应明确；仅在框架边界或有文档约定的转发边界使用 `*args` 和 `**kwargs`。
- 有多个可选值时优先使用 keyword-only 参数；有领域含义的布尔 flag 组合应替换为 options 类型、
  enum 或独立操作。
- 函数应聚焦单一操作，并通过对无效、缺失或 no-op 输入的提前返回保持浅平主路径。
- 每个函数返回一种稳定形态；不同结果具有不同含义时，使用具名结果、dataclass、enum 或异常。
- 在边界验证外部 mapping、序列化数据和无类型 provider 值，再构造类型化领域值。

## 导入与错误

- 遵循仓库的导入边界，并按本地风格组织标准库、第三方和第一方导入。
- 仅在需要时导入 typing helper，并使用项目支持的泛型语法。
- 对预期失败抛出精确的领域或集成异常；跨边界转换错误时保留有用的原因上下文。
- 只有边界能够有意且安全地隔离失败时，才捕获宽泛异常。
- assertion 用于内部不变量，不用于用户输入或可恢复的运行时失败。

## 异步与资源

- async 函数应标注 await 后产生的值，而不是 coroutine wrapper。
- 通过 context manager、`try/finally` 或所有者生命周期方法明确资源归属和清理。
- 在异步或 callback 边界前解析稳定依赖；需要当前值时再读取会变化的状态。

## 测试与工具

- 可复用测试 helper 和 fixture 应明确其输入与结果形态。
- 新类型标注暴露含义不明确的分支时，在改变行为前添加聚焦测试。
- 布局、导入格式、suppression 语法和配置阈值由仓库 formatter、linter 和 type checker 管理。
- 只有任务明确包含项目级工具变更时，才引入或替换 Python 工具。
