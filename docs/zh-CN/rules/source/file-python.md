# Python 指引

强度：`Default`

适用范围：跨项目的 Python API、类型、数据边界、失败和资源契约；不包括归属于仓库的
formatter、linter 和 type checker 策略。

## API 与类型契约

- 仅修改类型标注时保持行为不变。当类型暴露含义不明的运行时情形时，根据代码、测试或项目策略
  解决，不要选择新行为。
- 为公共或可复用边界的参数和返回值添加标注；仅执行副作用的函数使用 `-> None`。使用仓库所
  声明的 Python 版本范围支持的语法。
- 仅在运行时边界本身必然为动态时使用反射、monkey patch 和元编程，并将其限制在该边界。
- 仅对真正开放或转发型契约使用 `*args` 和 `**kwargs`；其他情况应明确命名参数。当一个签名具有多个
  独立可选值时，将参数设为 keyword-only。
- 结构化 API 使用 `Protocol`，数据形态使用 dataclass 或类型化领域类型，有限状态使用 `Literal`、
  enum 或具名类型。不要使用布尔 flag 或隐式 `None` sentinel 编码具有领域含义的状态组合。
- 仅在需要时导入 typing helper，并使用项目支持的泛型语法。

## 局部值与函数

- 在首次使用附近声明变量，为含义不明确或空的初始值添加标注，并让 nullable 值只存在于尽可能窄的
  路径中。
- 每个值名称只承担一个角色和一种类型，不要将其复用于不同的值。
- 函数应聚焦单一操作，并通过对无效、缺失或 no-op 输入的提前返回保持浅平主路径。

## 数据边界

- 在边界类型中明确集合是否可修改：修改不属于契约时，接受 `Mapping`、`Sequence` 和 `Iterable`
  等只读抽象；调用者必须允许修改时，要求可修改类型。
- 仅在真正的动态或无类型边界保留 `Any`，并在值进入类型化领域逻辑前对其进行验证或收窄。
- 在构造类型化领域值前，验证外部 mapping、序列化数据和无类型 provider 值。
- 每个函数返回一种稳定形态。不同结果具有不同含义时，使用具名结果、enum 或异常。

## 失败与资源

- 对预期失败抛出精确的领域或集成异常；跨边界转换错误时保留有用的原因上下文。
- 仅在拥有失败策略的边界捕获宽泛异常；重新抛出或转换该边界无法安全隔离的失败。
- assertion 用于内部不变量，不用于用户输入或可恢复的运行时失败。
- 协程函数应标注 await 后产生的值；异步生成器函数应标注异步迭代器或生成器类型。
- 在异步或 callback 边界前捕获稳定依赖；需要当前值时再读取会变化的状态。
- 每个已获取资源应有一个清理所有者，并明确所有权转移。对于保留所有权的每条路径，通过 context
  manager、`try/finally` 或所有者生命周期方法确保清理。

## 类型变更

- 新类型标注使某个分支含义不明确时，在进行已有证据支持的行为变更前，添加并运行用于确立当前行为的
  聚焦测试。
