# 项目工具

强度：`Mandatory`

适用范围：用于目标仓库安全执行命令、同步、状态修改、完整变更验证以及已有 Skill 交接的生成契约。

## 生成框架

生成一份由目标负责的 `.agents/rules/00-project-tools.md`，其类型为项目本地的普通 Mandatory
Rule。它的持续性政策只回答以下问题：Agent 如何安全执行仓库工具，观察到哪些源文件变更时需要
同步，什么权限允许状态修改，如何验证完整的变更集，以及现有 Skill 何时负责这项工作。

从当前目标证据推导 Rule 的适用范围、谓词到结果的映射、例外、优先级和所有权边界。保留有依据的
现有语义，并且只写入目标 Rule，除非已接受的请求明确授权其他目标变更。当状态修改权限、比较基准、
保留的行为，或缺失、冲突、仅适用于本机的证据仍可能导致实质不同的仓库级结果时，在写入前停止。

## 证据到政策的映射

- 检查仓库入口指导、工作区和包 manifest、运行时和工具链版本固定配置、仓库脚本、任务运行器配置、
  CI 工作流以及命令帮助。只有当证据表明必需的工作目录或运行时前置条件会影响受支持的调用能否成功
  时，才予以说明；应指向其当前责任方，而不是缓存可发现的值或清单。
- 从规范源开始，经由仓库自有的同步器，一直追踪到输出和只读漂移检查，覆盖每个后果显著的生成或同步
  界面。对于每个已确认的源文件变更谓词，说明必需的同步结果、存在时的仅检查替代方案，以及必须审查
  的生成 diff。引用负责该命令的界面；只有 Agent 无法从中可靠推导出准确调用时，才写出该调用。
- 检查脚本和当前帮助，以区分只读行为与状态修改行为，并确定选择器、更安全的模式、受影响路径和失败。
  将每项后果显著的状态修改与允许它的明确项目或用户权限放在一起，同时说明缺少该权限时必须采用的
  只读、限定范围或 dry-run 结果，以及需要检查的最终变更。工具存在、拥有写入权限或宽泛的任务描述
  都不授予权限。
- 根据声明的比较基准，结合版本控制状态与 diff、未跟踪路径、生成影响，以及牵涉的加载、生成、所有权、
  交付或运行时界面，确定实际变更集。把每个路径和受影响界面映射到项目指导、验证选择器、CI、测试与
  构建配置以及同步器检查中适用的非修复检查。列出每个未覆盖的路径或界面；只要仍有未覆盖项，或必需
  检查尚未通过，就不能声称已完成完整验证。
- 检查可发现的项目 Skill 及其调用指针。只有现有 Skill 已接受的触发条件和有界结果负责该工作时，才
  写出该 Skill 及其可观察触发条件。将持续生效的调用约束和交接条件保留在 Rule 中；将流程、顺序、
  恢复和结果处理留在 Skill 中。

根据目标 Rule 有依据的谓词和结果选择其组织方式，不要沿用本契约的标题。省略工具清单、环境快照、
命令目录、分步流程，以及已经由当前配置、命令帮助、脚本或 Skill 负责的行为。

## 所有权边界

- 将硬性的 API、生成源、能力所有权、交付、安装、依赖关系和契约演进政策保留在
  `Project Contracts` 中。当该责任方决定应采用哪种执行或同步结果时，引用它。
- 将建议性的目录放置、职责图和架构接缝判断保留在 `Project Structure` 中；本 Rule 可以写出其
  强制执行命令，但不能复述其政策。
- 将确定性机制保留在仓库自有脚本中。

## 验证与交接

根据目标的权威证据验证纳入的每项映射和准确命令，然后将生成的 Rule 交给当前的普通工件流程。
交接其证据和未解决的遗漏；只要存在未覆盖的路径或界面，就不能声称已完成完整验证。
